ファクトリーのループ早見表

無人ループの骨組み、ガード、セッションの手順、claude -p のオプション。実装は starter/factory.sh。

ループの骨組み

for i in 1..MAX_ITER:
    残り = passes:false の件数
    残り == 0 なら 完了で終わる              ← 完了判定
    ハッシュ = passes を除いた機能一覧のハッシュ
    claude -p <続きのプロンプト> --max-budget-usd …   ← 予算上限（セッション内）
    ハッシュが変わったら 停止                 ← 改竄検知
    残りが減らない回が MAX_STALL 回続いたら 停止   ← 停滞検知
MAX_ITER に達したら 停止                      ← 回数上限

4つのガードと予算上限

ガード見るもの防ぐ失敗
完了判定passes: false の件数終わったのに回り続ける
回数上限ループの回数終わりのない実行
停滞検知残り件数の変化同じ失敗の繰り返し
改竄検知passes 以外のハッシュテストを書き換えて合格にする
予算上限--max-budget-usd1回のセッションの中での暴走

ループのガードが判断できるのは、セッションが終わってからだけ。セッションの中の暴走は、claude -p 側の上限で止める。

コーディングエージェントの手順

  1. 状況をつかむ：pwd、ls、進捗ファイル、git log、残り件数
  2. 既存の機能を確かめる（新しい作業より先に）。壊れていたら passes: false に戻して直す
  3. passes: false のうち一番上の機能を 1つだけ 選ぶ
  4. 実装して、steps のとおりに確かめる
  5. 確かめられたときだけ passes: true にする（ほかのフィールドは変えない）
  6. 説明つきでコミットし、進捗ファイルに追記する

claude -p のオプション

オプション用途
-p "…"対話なしで1回実行して終わる（呼ぶたびに新しいセッション）
--output-format jsonresult・session_id・total_cost_usd を返す
--max-budget-usd N1回の実行の費用の上限
--permission-mode auto分類器が操作を1つずつ審査する
--permission-prompts none許可の確認を待たずに断り、先へ進む（無人実行向け。v2.1.259 以降）
--allowedTools "…"確認なしで使えるツールを列挙する
--bare手元の hooks・skills・CLAUDE.md を読み込まない（CI 向け。API キーが必要）
