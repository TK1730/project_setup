用語集

このコースのレッスンは、ここの用語で統一する。タグはファクトリーの4つの部品（仕様・実行・検品・記録）を表す。

全体

AIファクトリー（ソフトウェアファクトリー）
仕様を入力すると、エージェントが実装・テスト・記録までを無人で進める開発の仕組み。このコースでは「AIエージェントの開発工場」の意味で使い、NVIDIA の GPU インフラの意味では使わない。
ハーネス
モデルの周りに置く環境の全体。プロンプト、ツール、スクリプト、状態ファイル、テスト、制約などを含む。ファクトリーの性能はモデルだけでなく、ハーネスでも大きく変わる。[Anthropic]
Shapiro のレベル（0〜5）
AI を使った開発の段階。3＝人間が diff をレビューする／4＝仕様を書き、長時間走らせ、テストで確かめる／5＝ダークファクトリー。[Shapiro]
ダークファクトリー
レベル5。人間がコードを書かず、レビューもしない。製造業の「無人で消灯したまま動く工場」から来た言葉。StrongDM が実践している。[Willison]

部品

機能一覧（feature list）仕様
作るべき機能を並べた JSON。全項目を passes: false から始め、エージェントは passes だけを変えてよい。モデルが Markdown より書き換えにくいので JSON にする。
初期化エージェント実行
最初のセッションで1回だけ動き、機能一覧・init.sh・進捗ファイル・最初のコミットを用意する。
コーディングエージェント実行
2回目以降の各セッションで動き、1機能ずつ進め、終わるときに記録を残す。初期化エージェントとは、最初のユーザープロンプトだけが違う。
init.sh実行
開発サーバーなどを起動するスクリプト。エージェントが毎回起動方法を調べ直さずに済む。
ヘッドレス実行（claude -p）実行
Claude Code を対話なしで動かす。--output-format json（結果とコストを返す）、--permission-mode、--permission-prompts none（無人実行）、--max-budget-usd、--bare（環境ごとの設定を読み込まない）。[Docs]
git worktree実行
1つのリポジトリから作業フォルダを複数作る機能。エージェントを並列に動かしても、互いの作業がぶつからない。
ガード実行
無人ループを止める条件。完了判定（残り0件）、回数上限、停滞検知（残り件数が減らない）、改竄検知（passes 以外が変わった）、予算上限（--max-budget-usd）。[早見表]
機械的な強制検品
プロンプトでお願いするのではなく、スクリプト・linter・CI で決まりを守らせること。例：機能一覧の改竄検知。
E2E 検証検品
人間のユーザーと同じ操作で確かめる（ブラウザ自動化など）。Anthropic は、単体テストや curl だけでは見落としが多かったと報告している。
シナリオ（ホールドアウト）検品
コードベースの外に置き、エージェントに見せない E2E のユーザーストーリー。エージェントがテストをズルして通すのを防ぐ。
satisfaction検品
StrongDM の指標。全シナリオを何度も実行し、ユーザーを満足させたと思われる実行の割合を出す。「テストが緑かどうか」の二択の代わりに使う。
Digital Twin Universe（DTU）検品
外部サービス（Okta、Slack など）の動きを再現したクローン。レート制限やコストなしで、大量のシナリオを実行できる。
進捗ファイル（progress file）記録
各セッションが何をしたかを書く作業ログ（例：claude-progress.txt）。新しいセッションは、まずこれと git log を読む。
docs を正とする（system of record）記録
リポジトリ内の docs を、エージェントにとっての唯一の正しい情報源にする。docs の整合性は linter と CI で強制する。[OpenAI/InfoQ]
