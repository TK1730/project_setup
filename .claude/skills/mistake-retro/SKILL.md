# mistake-retro

指摘されたミスについて、改善案を書き出す。採用するかはユーザーが決める。

## 1. ミスを 1 文にする

今回のミスを「何をしたか / 本来どうすべきだったか」の 1 文にまとめ、ユーザーに確かめる。ユーザーの言葉があれば、そのまま引用する。

## 2. 過去の記録と照らし合わせる

次の材料を読み、同じ種類のミスが前にもあったかを確かめる。

- `AGENTS_LEARNING.md` の各節の「再発防止チェックリスト」
- メモリの `type: feedback` のファイル
- `docs/AGENTS.md` と `.claude/skills/` の関連する記述

結果は次のどちらかである。

- 初めてのミス: 対策がまだどこにも書かれていない。
- 再発: 対策は書かれているのに守られなかった。この場合は、対策を書き足すのではなく、**なぜ効かなかったか**を考える。たとえば、書いた場所が作業中に読まれない、書き方があいまい、確かめる手順になっていない、などである。

## 3. 改善案を出す

改善案は最大 3 つにする。それぞれに次の 4 つを書く。

- 変える場所（ファイルと見出し）と、変える内容の差分
- 根拠（どの記録から出た案か）
- 分類（全作業共通 / coding / docs / 指示の受け方）
- 確認用の依頼文（このミスが起きた依頼を、そのまま再現できる 1 文）

次のファイルは、改善案の対象にしても書き換えない。「メンターへの提案」として書くだけにする。

- ルート直下の `AGENTS.md`
- `~/.antigravity-gate/`・`~/.claude-gate/` 配下のファイル
- ゲートの hook

## 4. 書き出す

`.local/harness/proposals/YYYY-MM-DD-<ミスの短い名前>.md` に書き出し、ユーザーに要点を伝える。ハーネスのファイルはここでは変えない。

ユーザーが採用した案だけを反映する。反映したら、`AGENTS_LEARNING.md` に節を足すか、既存の節の「再発防止チェックリスト」を更新する。
