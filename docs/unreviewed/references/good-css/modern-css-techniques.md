# good-css のモダン CSS テクニック要約

この文書は、モダン CSS のテクニックを集めた 1 ページのサイト [good-css](https://good-css.com/)（最終更新 2026-10-10）の要約であり、全文の翻訳ではない。サイトは、ブレークポイントの段組みやラッパー要素、スクリプトの代わりに、それだけで状況に合わせて変わる CSS の宣言を使うことを勧める。主な読み手は AI エージェントで、開発者も対象にしている。

## good-css の概要

- 書き手・運営者: ページには書かれていない。各テクニックには、元になった専門家の名前が出典として付いている。
- 目的: サイトの説明文は "Strong opinions about modern CSS technique, borrowed from experts, for agents to know and reach for."（引用）である。専門家から借りたテクニックを、エージェントが知っていて使えるようにすることを目指している。
- 前提: どのテクニックも素の CSS で書かれていて、クラス名、ファイル構成、フレームワークに依存しない。例のクラス名は仮のもので、自分の使っているスタイルの仕組みに置き換えて使う。
- 基本の考え方: ブレークポイントを何段も重ねるより、1 つの宣言が自分で合わせるほうを選ぶ。スクリプトより CSS の機能を選ぶ。JavaScript は、それがなくても動くものに機能を足すときだけ使う。
- 構成: 8 つの分類に、計 47 件のテクニックを並べている。
- 対応ブラウザ: 対応ブラウザの下限は決めていない。各テクニックに主要ブラウザの対応バージョンが書いてあるので、自分のプロジェクトの対象ブラウザと照らし合わせる。

## 各テクニックの書き方

各テクニックは、同じ順番の項目で書かれている。

1. 使う場面（When）
1. CSS の例
1. うまくいく理由（Why）
1. 守るべきルール（Rules）
1. ブラウザの対応状況（Support）
1. 出典（Sources）

以下では、テクニックごとに「使う場面」「要点」「主なルール」を短くまとめる。対応バージョンと出典は、サイトの各テクニックを参照する。

## 基礎（Foundations、6 件）

- リセット: 新しいプロジェクトを始めるときに使う。既存のプロジェクトには 1 つずつ足す。全要素に `box-sizing: border-box` と `min-width: 0` を付け、`text-wrap`、`scrollbar-gutter: stable`、`min-height: 100svh`、入力欄の文字サイズを 16px 以上にする指定などを入れる。`min-width: 0` は、flex や grid の子が中身より小さく縮めるようにするためのものである。ズームを `user-scalable=no` で止めてはいけない。
- 論理プロパティ: left、right、top、bottom の代わりに `padding-inline` や `margin-block-end` などを使う。向きが `dir` や `writing-mode` に従うので、右から左に書く言語のページでも 1 組の指定で左右が入れ替わる。4 つの値をまとめて書く `margin` などは物理方向のままなので、`-inline` と `-block` の形を使う。
- OKLCH の色: 基本の色を `oklch()` で書き、ホバー色や薄い色は `color-mix(in oklch, …)` で作る。sRGB で混ぜると色が灰色に寄るが、OKLCH なら色相が保たれる。灰色、白、黒は色相を `none` にする（`0` は赤を表すため）。
- ライトとダークで共通の色トークン: `:root` に `color-scheme: light dark` を指定し、各トークンを `light-dark()` で書く。テーマの切り替えは `color-scheme` を変えて行い、トークンを定義し直さない。
- `clamp()` による可変サイズ: 文字サイズや余白を画面幅に合わせて変える。中央の値は `rem + vw` の形にし、`vw` だけで書かない。文字サイズの最大値は最小値の 2.5 倍以下に抑える（500% ズーム時の WCAG 1.4.4 のため）。
- 文字と余白で共通の可変スケール: 文字サイズが 3 種類を超える設計で使う。6 つの入力値から `pow()` で各段のサイズを計算させ、余白も同じスケールの倍数で決める。ブレークポイントごとの表や外部の生成ツールが要らなくなる。

## レイアウト（Layout、8 件）

- はみ出し領域付きのコンテンツグリッド: ページ全体の入れ物に使い、中央寄せの `max-width` ラッパーの代わりにする。グリッドの線に名前を付け、本文の幅、少し広い幅、画面いっぱいの幅を選べるようにする。子要素はすべてどこかの列に置く。
- 内在的なグリッド: 同じ大きさのカードを並べるときに、ブレークポイントごとの列数の指定の代わりに使う。`repeat(auto-fit, minmax(min(100%, 16rem), 1fr))` の形で、列数が入れ物の幅で決まる。
- カード間で共有する subgrid の行: 行に並ぶカードのタイトル、本文、フッターの高さを揃える。各カードが親の行を `subgrid` で使うので、一番長いタイトルが行の高さを決める。
- 自分で折り返すサイドバー: 片方に理想の幅があり、もう片方が残りを使う 2 つ組で使う。flex の `flex-grow` の差を使い、本体が入れ物の半分を下回るときに縦に並ぶ。
- コンテナクエリとコンテナ単位: 幅の違う場所に置かれる部品で使う。画面幅ではなく、一番近いコンテナの幅で判定する。`cqi` は、そのコンテナの幅の 1% である。
- grid で重ねるレイヤー: 画像の上の文字やカードのバッジなど、要素を重ねるときに使う。すべての子を同じセル（`grid-area: 1 / 1`）に置くので、入れ物は一番大きい子の大きさになる。
- safe な配置: はみ出す可能性がある入れ物で中央寄せするときに `safe center` を使う。普通の `center` では、はみ出した先頭側がスクロールでも見えなくなる。
- `hidden` より `overflow: clip`: スクロールが要らない切り取りに使う。`hidden` はスクロールコンテナを作るので、内側の `position: sticky` が効かなくなることがある。

## 余白と形（Spacing and shape、4 件）

- 隣の節によって変わる節の余白: CMS のように節の並び順が変わるページで使う。`:has(+ B)` と `A + B` で、特定の 2 つの節が接する部分だけ余白を変える。
- 親が決める兄弟間の余白: 縦に並ぶ要素の間隔を、子ではなく親が決める。自分で管理する部品では flex の `gap` を、CMS の出力のように管理できない中身ではマージンを使う形（`* + *`）を使う。
- auto マージンで 1 つだけ離す: カードの操作ボタンを下端に寄せるなど、1 つの要素だけを離したいときに使う。auto マージンは、その側の空きをすべて使う。
- 同心円の入れ子の角丸: 角丸の親の中に角丸の子を置くときに、外側の角丸を「内側の角丸 + 余白」にする。中心が同じでないと、2 つの曲線が平行に見えない。

## 文字とメディア（Text and media、5 件）

- 長い文字列の折り返し・省略・行数制限: 名前や URL など、ユーザーや CMS が入れる文字列で使う。ルートに `overflow-wrap: break-word` を付け、1 行は省略記号で、複数行は行数を数えて切る。省略してよいのは、別の場所で全文を読める文字列だけである。
- どんな画像でも収まる枠: 中身を管理できないサムネイルやアバターで使う。`aspect-ratio` で読み込み前から場所を確保し、`object-fit: cover` で歪めずに埋める。ロゴには `contain` を使う。
- 等幅の数字: 価格、表、タイマーで `font-variant-numeric: tabular-nums` を使う。数字の幅が揃うので、値が変わっても周りが動かない。全体には適用しない。
- `text-box` で文字に合わせて中央に置くラベル: ボタンやバッジの 1 行のラベルで使う。行の高さを大文字の上端とベースラインで切り詰めるので、上下の余白が同じに見える。`*` には使わない。
- 隣の文字で大きさが決まるアイコン: ラベルの横のアイコンを `cap`、`em`、`lh` の単位で指定する。アイコンの大きさを px で決めない。

## 操作（Interaction、8 件）

- `:focus-visible` による 1 つのフォーカスリング: すべての操作できる要素のフォーカス表示に使う。キーボード操作のときだけリングが出る。`outline: none` は書かない。
- ホバーできる環境だけのホバー: すべての `:hover` を `@media (hover: hover) and (pointer: fine)` の中に書く。タッチ端末では、タップ後もホバーの状態が残るためである。
- 押したときの反応: ボタンに `:active` で少しだけ縮む表示（0.95〜0.98 倍）を付ける。`click` を待たずにすぐ反応する。
- 見た目より広い押せる範囲: 44px より小さいアイコンボタンなどで、疑似要素を使って押せる範囲を 44px まで広げる。`min()` を使うので、もともと大きいボタンには影響しない。
- 1 つのリンクでカード全体を押せるようにする: カード内の本物のリンクの疑似要素でカード全体を覆う。スクリーンリーダーが読み上げるのは短いリンク文字列だけになる。フォーカスリングは `:has()` でカードに移す。
- 親やページの状態に使う `:has()`: 子の内容や状態で親のスタイルを変える。モーダル表示中のスクロール固定にも使える。スクリプトでクラスを付ける必要がなくなる。
- `:user-invalid` による入力のフィードバック: ユーザーが入力した後だけ、入力欄の状態を表示する。色だけでなく文字やアイコンも添える。サーバー側の検証は別に必要である。
- 中身に合わせて伸びる入力欄: `field-sizing: content` で、`textarea` が文字量に合わせて伸びる。高さは固定にせず、最小値と最大値で範囲を決める。

## 動き（Motion、6 件）

- 選んだ人だけの動き: 動きのある遷移を `prefers-reduced-motion: no-preference` の中に書く。まず状態の変化を作り、その後で動きを足す。透明度や色の変化は外に置いてよい。
- 動きのトークン: イージングを ease-out と ease-in-out の 2 種類のトークンにまとめる。UI に `ease-in` は使わず、遷移は 300ms 以下にし、`transition: all` は使わない。
- `@property` でカスタムプロパティを遷移させる: 1 つの状態の変化で複数の値を一緒に動かすときに使う。型を登録すると、ブラウザがカスタムプロパティを補間できる。
- 描き直さずにフェードする影: ホバーで浮くカードの影を、疑似要素の透明度の変化で切り替える。`box-shadow` を直接遷移させるより、描画の回数が大きく減る。
- ページをまたぐ View Transitions: 複数ページのサイトで、両方のページに `@view-transition { navigation: auto; }` を書くと、ページ遷移でクロスフェードする。クライアント側のルーターが要らない。
- 選択中の項目へ滑るインジケーター: タブの下線などを、アンカー位置指定で選択中の項目に合わせる。位置と大きさをスクリプトで測る必要がない。

## 表示と非表示（Show and hide、4 件）

- `display: none` からの出入りの遷移: ダイアログやポップオーバーで、`@starting-style` で開く前の状態を、`allow-discrete` で閉じるときの遷移を作る。`scale(0)` から始めず、`scale(0.95)` と透明から始める。
- トリガーに合わせて置くポップオーバー: ドロップダウンメニューを `position-area` でボタンの周りに置き、はみ出すときは反対側に回り込ませる。
- 高さが動くアコーディオン: `<details>` の開閉を、`interpolate-size` と `::details-content` で高さを動かして見せる。
- `clip-path` で見せる: 高さが分からない重なるパネルを、`clip-path` の切り取りで見せる。高さを動かさないので、レイアウトが変わらない。

## スクロールと画面（Scroll and viewport、6 件）

- ブラウザ標準のスクロールで作るカルーセル: 横に並ぶカードを、スクロールスナップで作る。スワイプやキーボード操作はブラウザに任せ、矢印ボタンだけ小さなスクリプトで動かす。`transform` で動かしたり、ホイールやタッチの処理を自作したりしない。
- 固定ヘッダーとフッターの間のスクロール領域: モーダルの本文やチャットの一覧で、パネルを flex の縦並びにし、本文だけをスクロールさせる。パネルには高さの上限が必要である。
- はみ出したときだけ効くスタイル: タブ列などで、中身がはみ出したときだけ端をぼかす。スクロールで進むアニメーションは、スクロールする中身がなければ動かないことを使う。
- 固定ヘッダーに隠れないページ内リンク: `html` に `scroll-padding-block-start` を指定し、リンク先がヘッダーの下に隠れないようにする。
- デスクトップでの跳ね返りをなくす: アプリのようなページで、`overscroll-behavior-y: none` を使う。タッチ端末では引っ張って更新する操作を残すため、元に戻す。
- ノッチを避ける: スマートフォンの固定ヘッダーや下部バーで、`viewport-fit=cover` と `env(safe-area-inset-*)` を使う。普通のページ本文には要らない。

## エージェント向けのスキルファイル

サイトは、エージェントが読むためのスキルファイル（`SKILL.md`）も公開している。中身は次のとおりである。

- 先頭に、どの CSS でも守る基本ルール（論理プロパティ、`oklch()`、`clamp()`、ホバーのメディアクエリ、`:focus-visible`、動きを減らす設定への配慮、`overflow: clip` など）を置く。
- 8 つの分類ごとの参照ファイル（`references/layout.md` など）と、それぞれを読むべき作業を表で示す。
- 意図的に入れなかった書き方（`*` への `text-box` など）も挙げている。
- 素の CSS だけでなく、Tailwind、StyleX、CSS-in-JS、インラインスタイルにも当てはまるとしている。
- 動きの設計とレビューは、Emil Kowalski のスキルが入っていればそちらに任せるとしている。
