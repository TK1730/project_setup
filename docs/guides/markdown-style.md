# Markdown の書き方

Markdown の記法のルール。ソースのままでも読みやすく、どのレンダラーでも同じに見えることを目指す。

## 見出し

- 見出しは `#` で書く（ATX 形式）。`=` や `-` の下線形式は使わない。
- `#` の後にスペースを入れ、前後に空行を置く。
- 見出し名は、文書の中で重複しない完全な名前にする（「概要」ではなく「Foo の概要」）。アンカーが分かりやすくなる。

## 行と空白

- 英語の文は 80 文字程度で折り返す。リンク、表、見出し、コードブロックは例外である。
- 日本語の文は折り返さない。段落の途中で改行すると、表示に余計な空白が入るためである。
- 行末に空白を置かない。改行したい場合は行末にバックスラッシュを使うが、段落（空行）で足りるなら使わない。

## リスト

- 番号付きリストは、番号をすべて `1.` と書く（lazy numbering）。項目を足したり並べ替えたりしても、番号を振り直さずに済む。
- 入れ子は 4 スペースでインデントする。

```markdown
1.  Foo.
1.  Bar.
    1.  Foofoo.
1.  Baz.
```

## コード

- 複数行のコードは、インデントではなくフェンス（バッククォート 3 つ）で囲み、言語を必ず指定する。
- コピーして端末に貼るコマンドは、改行をバックスラッシュでエスケープする。
- ファイル名、コマンド、項目名などはインラインコードで書く（`README.md` など）。

## リンク

- リンクテキストは内容が分かる語句にする。「ここ」「link」や URL そのままは使わない。
- 長い URL は参照リンク（`[text][id]`）に分け、定義は最初に使った節の末尾に置く。短いリンクには使わない。
- docs 内の文書へは `/` で始まる Bundle 基点のパスでリンクする（例: `/guides/writing.md`）。`../` を使った相対パスは使わない。詳しくは [Open Knowledge Format 運用ガイド](/guides/open-knowledge-format.md) を参照する。

## 表

- 表は、素早く見比べたい表形式のデータにだけ使う。
- 空のセルが多い、列が多すぎる、セルに長い文章が入る場合は、リストと小見出しにする。
- 表のセルは短く保つ。長いリンクは参照リンクにする。

## HTML と装飾

- 標準の Markdown で書き、HTML タグは使わない。HTML は読みやすさと移植性を下げる。
- 太字などの強調は多用しない。
- 図は Mermaid のコードブロックで書く。

## 画像

- 画像は控えめに使う。説明するより見せるほうが簡単な場合（画面操作など）に限る。
- 代替テキストを必ず付ける。
