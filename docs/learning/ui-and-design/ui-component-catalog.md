# UI コンポーネント（見た目と名前）の定番カタログ

「こういう見た目の部品を作りたいけれど、英語やデザインシステム上で何という名前か分からない」「似た部品のどれを使うべきか迷う」という課題を解決するための定番 UI 部品名鑑である。WAI-ARIA Authoring Practices Guide（APG）、shadcn/ui、および The Component Gallery の分類に準拠し、実務で頻出するコンポーネントを5つのカテゴリに分けて整理している。画面設計や実装の前に本カタログを参照することで、適切な名称でコンポーネントを検索・選定し、アクセシビリティと操作性に優れた UI を構築できる。

## 1. 情報を整理・開閉する部品

画面内の情報量をコントロールし、関連する要素を視覚的にグループ化したり段階的に開示したりするためのコンポーネント群である。

| 部品名（英語 / 日本語）                                                             | どんな見た目と動きか                                                                                                                                                          | いつ使うか（似た部品との使い分け）                                                                                                                                                                      |
| :---------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Accordion**（アコーディオン）                                                     | 複数の見出し項目が縦に並び、見出しをクリックするとその下に隠れていた詳細コンテンツが上下に開閉する部品。設定により「同時に1つだけ開く」か「複数同時に開ける」かを制御できる。 | FAQ（よくある質問）や設定画面のセクション分けなど、同じ階層のトピックが複数並んでおり、ユーザーが関心のある項目だけを開いて読みたい場合に使う。                                                         |
| **Collapsible / Disclosure**（コラプシブル / ディスクロージャー：単一の折りたたみ） | 「詳細を表示 / 隠す」といった1つのトリガーボタンと、それに連動して開閉する1つのコンテンツ領域で構成されるシンプルな折りたたみ部品。                                           | ログの全文表示や検索の「詳細フィルタを開く」など、単独の補足領域を開閉したい場合に使う。複数項目を並べて管理したい場合は `Accordion` を使う。                                                           |
| **Tabs**（タブ）                                                                    | 横並び（または縦並び）の見出しボタンを切り替えることで、同じ表示領域の中身を別のビューへ即座に切り替える部品。                                                                | 「概要 / レビュー / 仕様」のように、同じ文脈・同じ重要度を持つ別視点のコンテンツを、画面遷移せずに省スペースで切り替えたい場合に使う。一覧を縦に並べて比較させたい場合は `Accordion` の方が適している。 |
| **Card**（カード）                                                                  | 枠線（ボーダー）や影（シャドウ）、背景色で囲まれた矩形のコンテナで、画像・タイトル・概要テキスト・アクションボタンなどの関連情報を1つの塊として表現する。                     | 商品一覧、記事リスト、ダッシュボードのサマリーパネルなど、独立した情報のまとまりをグリッドやリストで並べる場合に使う。                                                                                  |
| **Separator / Divider**（セパレーター / ディバイダー：区切り線）                    | 水平または垂直に引かれる細い線（`hr` 要素相当）で、セクション間やメニュー項目間の視覚的・意味的な境界を示す。                                                                 | `Card` で囲むほどではないものの、要素同士のグループの違いや話題の切り替わりを控えめに示したい場合に使う。                                                                                               |

## 2. 画面の上に重なる部品（Overlay）

現在の画面コンテキストを維持したまま、最前面に浮かび上がって追加情報や操作を提示するコンポーネント群である。背景操作をブロックするかどうか（モーダル性）と、ユーザーに求めるアクションの重さで使い分ける。

| 部品名（英語 / 日本語）                     | どんな見た目と動きか                                                                                                                                                                                    | いつ使うか（似た部品との使い分け）                                                                                                                                                                                                    |
| :------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Dialog / Modal**（ダイアログ / モーダル） | 画面中央に浮かび上がり、背景を暗転（オーバーレイ）させて背後の画面操作を止めるウィンドウ。フォーカストラップ（Tab キー移動がダイアログ内で完結する制御）と `Esc` キーや背景クリックで閉じる挙動を持つ。 | 新規作成フォームや詳細設定など、現在の画面から離れずにユーザーの注意を1つのタスクに集中させたい場合に使う。                                                                                                                           |
| **Alert Dialog**（アラートダイアログ）      | 見た目は `Dialog` に似ているが、背景クリックなどでは閉じず、「キャンセル」「削除する」といった明示的なボタン操作をユーザーに強制するダイアログ（WAI-ARIA の `alertdialog` ロールを持つ）。              | データ削除の確認や未保存データの破棄確認など、取り消せない重要な操作の前に必ずユーザーの意思確認を取りたい場合に使う。単なる情報入力や閲覧には通常の `Dialog` を使う。                                                                |
| **Drawer / Sheet**（ドロワー / シート）     | 画面の上下左右の端（エッジ）からスライドして現れるパネル。背景操作を止めるモーダル型と、横並びで開いたまま操作できる非モーダル型がある。                                                                | モバイルのナビゲーションメニュー、一覧画面で選択した行の詳細プレビュー、項目数の多いフィルタ設定など、縦に長いコンテンツやメイン画面の補助パネルを表示したい場合に `Dialog` の代わりとして使う。                                      |
| **Popover**（ポップオーバー）               | トリガーとなるボタンを押した際、その要素のすぐ近くに吹き出し状に浮かび上がる小さなパネル。パネルの内部にボタン、リンク、入力欄などの操作要素を配置できる。                                              | カレンダーの日付選択（Date Picker）、通知一覧の小窓、簡単なフィルタ設定など、特定のボタンに紐づく軽量な操作パネルを出したい場合に使う。画面全体の作業を中断させる重い処理には `Dialog` を使う。                                       |
| **Tooltip**（ツールチップ）                 | アイコンやボタンにマウスホバーまたはキーボードフォーカスした際、要素の近くに小さく表示される短い補足テキスト。                                                                                          | アイコンのみのボタンの意味（「編集」「コピー」など）や、省略されたテキストの全文を補足したい場合に使う。**Tooltip の中にはボタンやリンクなどのクリック可能な要素を置いてはならない**（操作要素を入れる場合は必ず `Popover` を使う）。 |

### Overlay 部品の選び方（判断フロー）

1.  ホバーやフォーカスだけで短い説明文を出したい（中にボタンは置かない）場合は `Tooltip` を選ぶ。
1.  ボタンを押した近くに小さな操作パネルを出したい場合は `Popover` を選ぶ。
1.  破壊的操作（削除・破棄）の最終確認を強制したい場合は `Alert Dialog` を選ぶ。
1.  画面端から縦長のメニュー・詳細パネル・フィルタを出したい場合は `Drawer` / `Sheet` を選ぶ。
1.  画面中央で独立した入力フォームや完結したサブタスクを行わせたい場合は `Dialog` / `Modal` を選ぶ。

## 3. 通知・状態を示す部品（Feedback）

システムからの通知、警告、ステータス、および非同期処理の進行状況をユーザーに伝えるためのコンポーネント群である。

| 部品名（英語 / 日本語）                                          | どんな見た目と動きか                                                                                                                                                                 | いつ使うか（似た部品との使い分け）                                                                                                                                                           |
| :--------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Toast / Snackbar**（トースト / スナックバー）                  | 画面の隅（右下や上部など）に数秒間だけ表示され、自動的に消える一時的な通知バー。直前の操作を取り消す「元に戻す（Undo）」ボタンを伴うこともある。                                     | 「保存しました」「クリップボードにコピーしました」など、ユーザーの作業を妨げずに完了を伝えたい軽いフィードバックに使う。見落とすと困る重要なエラーには使わず、`Alert` を画面内に常駐させる。 |
| **Alert / Banner / Callout**（アラート / バナー / コールアウト） | ページ内やフォームの上部に常駐して表示される、アイコンと色付きの枠（情報・成功・警告・エラー）を持ったメッセージ領域。自動的には消えない。                                           | 入力エラーの要約、システムメンテナンスの告知、利用上の重要な注意事項など、ユーザーが確実に読み取るべきメッセージを表示する場合に使う。一時的な完了通知には `Toast` を使う。                  |
| **Badge / Chip / Tag**（バッジ / チップ / タグ）                 | テキストや数字を囲む角丸の小さなラベル。未読件数の丸い数字、ステータスの小片、削除（×）ボタン付きのカテゴリラベルなどのバリエーションがある。                                        | 「公開中 / 下書き」といった状態の明示、記事のカテゴリ表示、通知アイコン右上の未読カウント表示に使う。長文のメッセージを表示したい場合は `Alert` を使う。                                     |
| **Skeleton**（スケルトン）                                       | データ読み込み中に、最終的に表示されるカードやテキスト行・アバター画像の形状を模した灰色の枠（プレースホルダー）を表示し、シマー（光のアニメーション）で通信中であることを示す部品。 | ページ初期表示やカード一覧の取得など、レイアウトの骨格があらかじめ分かっており、読み込み完了時の画面ガタつき（Layout Shift）を抑えて体感速度を向上させたい場合に使う。                       |
| **Spinner / Progress**（スピナー / プログレスバー）              | `Spinner` は回転する円形アイコンで処理中を示し、`Progress` は横長のバーが 0% から 100% へ伸びることで処理の達成度合いを示す。                                                        | ボタン押下後の短時間の通信待ちや全体の所要時間が不明な処理には `Spinner` を使い、ファイルアップロードや複数ステップのバッチ処理など進捗率（%）を算出できる処理には `Progress` を使う。       |

## 4. 入力・選択する部品（Form / Input）

ユーザーからデータや設定値を受け取るフォーム系のコンポーネント群である。選択肢の数、単一選択か複数選択か、値の反映タイミングによって明確に使い分ける。

| 部品名（英語 / 日本語）                                            | どんな見た目と動きか                                                                                                                             | いつ使うか（似た部品との使い分け）                                                                                                                                                                        |
| :----------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Select**（セレクト：ドロップダウン選択）                         | クリックすると選択肢のリストが下に開き、その中から1つ（または複数）の値を選んで入力欄にセットする部品。                                          | 都道府県やロール選択など、あらかじめ決まった選択肢（目安として5〜15個程度）から1つを選ばせたい場合に使う。選択肢が2〜4個と少ない場合は、最初から全選択肢が見える `Radio Group` の方が操作手数を減らせる。 |
| **Combobox / Autocomplete**（コンボボックス / オートコンプリート） | テキスト入力欄とドロップダウンリストが合体した部品で、文字を入力すると選択肢がリアルタイムに絞り込まれる。                                       | 選択肢が数十〜数百件以上ある場合（国名、ユーザー検索、タグ検索など）、スクロールだけで探すのが困難な場面で `Select` の代わりに使う。                                                                      |
| **Radio Group**（ラジオグループ：ラジオボタン）                    | 複数の丸い選択肢が最初から画面に並べて表示され、その中から排他的に1つだけを選べる部品。                                                          | 選択肢が2〜4個程度と少なく、すべての選択肢を最初から比較させた上で1つだけ選ばせたい場合（配送方法、公開範囲など）に使う。複数選べるようにしたい場合は `Checkbox` を使う。                                 |
| **Checkbox**（チェックボックス）                                   | 四角い枠をクリックしてチェックマーク（レ点）を付け外しする部品。複数並べて任意の個数を選ばせる使い方と、単体で同意の有無を確認する使い方がある。 | 興味のあるカテゴリの複数選択や、「利用規約に同意する」といった ON/OFF を表現する場合に使う。通常は最後に「保存」「送信」ボタンを押したタイミングで値が確定する。                                          |
| **Switch / Toggle**（スイッチ / トグル）                           | 物理的な電源スイッチのように左右にスライドして ON / OFF を切り替える部品。                                                                       | ダークモードの切り替えや通知設定の有効化など、**「保存」ボタンを押さずとも、切り替えた瞬間にシステムへ即座に効果が反映される設定項目**に使う。フォーム送信時にまとめて送る項目には `Checkbox` を使う。    |
| **Slider**（スライダー）                                           | 横長のトラック（レール）上にあるつまみ（Thumb）を左右にドラッグして、最小値から最大値までの連続的な数値や範囲を選択する部品。                    | 音量調整、画像の拡大率、価格帯の絞り込みなど、厳密な数値入力よりも直感的な加減調整が適している場合に使う。正確な数値を入力させたい場合は数値用の `Input` を併用または優先する。                           |

## 5. 移動・操作メニューの部品（Navigation / Menu）

画面間の移動を助けたり、コンテキストに応じたアクション（操作コマンド）を呼び出したりするためのコンポーネント群である。

| 部品名（英語 / 日本語）                          | どんな見た目と動きか                                                                                                                                                                                                                    | いつ使うか（似た部品との使い分け）                                                                                                                                                                                                    |
| :----------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Dropdown Menu**（ドロップダウンメニュー）      | 「…」アイコン（三点リーダー）や「操作」ボタンを押すと下に開くメニューリストで、クリックすると各項目に割り当てられたアクションを実行する。                                                                                               | テーブル行の「編集 / 複製 / 削除」や、ユーザーアイコンを押したときの「プロフィール / ログアウト」など、**「フォームの値を選ぶ」のではなく「操作（コマンド）を実行する・画面遷移する」**場合に使う（値を選ぶ場合は `Select` を使う）。 |
| **Breadcrumb**（ブレッドクラム：パンくずリスト） | ページ上部に `ホーム > カテゴリ > 現在のページ` のように階層構造を横並びのリンクで示す部品。                                                                                                                                            | 階層が深い Web サイトや管理画面において、ユーザーが現在どの階層にいるかを把握させ、上位階層へ1クリックで戻れるようにしたい場合に使う。                                                                                                |
| **Pagination**（ページネーション：ページ送り）   | 一覧の下部に `前へ 1 2 3 ... 10 次へ` のようなページ番号ボタンを並べ、大量のデータをページ単位で分割表示・移動する部品。                                                                                                                | 検索結果や管理画面のテーブルなど、全件数や現在位置を把握しながら特定のページへジャンプしたい場合に使う。                                                                                                                              |
| **Command Palette**（コマンドパレット）          | キーボードショートカット（`⌘K` や `Ctrl+K`）や検索バーのクリックで画面中央に開き、文字入力によってページ移動・コマンド実行・横断検索をまとめて行えるモーダル型の操作パネル（shadcn/ui では `Command` コンポーネントとして提供される）。 | 機能や画面数が多いアプリケーションで、マウスでメニューを辿らずにキーボードだけで素早く目的の画面へ移動したりアクションを実行したりするパワーユーザー向けの導線として使う。                                                            |
