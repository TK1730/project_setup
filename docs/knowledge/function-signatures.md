# 関数のシグネチャの読み方と決め方

シグネチャ（signature）とは、関数の「名前・受け取るもの（引数）・返すもの（戻り値）」を書いた 1 行のことで、中身（`{ }` の中）は含まない。呼び出す側はシグネチャだけを見て関数を使うので、シグネチャは「呼ぶ側と呼ばれる側の約束」になる。中身を書く前にシグネチャを決めると、何を作るかがはっきりする。

## シグネチャとは

次の Go の関数で、1 行目の `{` の手前までがシグネチャである。

```go
func (s *Store) Find(ctx context.Context, id string) (Item, error) {
	// ここから下は中身。シグネチャには含まない
}
```

1 行目を部品に分けると、次のようになる。

| 部品       | この例                             | 意味                                                             |
| :--------- | :--------------------------------- | :--------------------------------------------------------------- |
| レシーバー | `(s *Store)`                       | どの型のメソッドか。`Store` 型の値 `s` から `s.Find(...)` と呼ぶ |
| 名前       | `Find`                             | 何をする関数か                                                   |
| 引数       | `(ctx context.Context, id string)` | 呼ぶ側から受け取るもの。`名前 型` の組を `,` で並べる            |
| 戻り値     | `(Item, error)`                    | 呼ぶ側に返すもの。2 つ以上なら `( )` で囲む                      |

この 1 行を日本語で読むと、「`Store` の `Find` は、`ctx` と文字列の `id` を受け取って、`Item` とエラーを返す」となる。

TypeScript でも考え方は同じで、書く順番が違うだけである。

```typescript
function find(id: string): Promise<Item> {
  // 中身
}
```

- 引数は `名前: 型` の順に書く。
- 戻り値の型は `)` の後ろに `: 型` で書く。

## シグネチャが約束になる理由

呼ぶ側は、中身を読まずにシグネチャだけで関数を使う。

```go
item, err := store.Find(ctx, "abc")
```

- 呼ぶ側が知っている必要があるのは、「`Find` に `ctx` と `id` を渡せば、`Item` と `error` が返る」ことだけである。
- 中身（SQL を使うか、ファイルを読むか）は、シグネチャを変えない限り自由に書き換えられる。
- 逆に、シグネチャを変えると、呼んでいる側をすべて直す必要がある。

そのため、シグネチャは中身より先に、呼ぶ側の立場で決める。

## シグネチャの決め方

次の 3 つの問いに順に答える。

1. 名前: この関数は何をするか。
   - 動詞から始める（`Find`、`Save`、`Delete` など）。
   - 呼ぶ側が名前だけで用途を推測できるようにする。
1. 引数: 呼ぶたびに変わる値は何か。
   - 呼ぶたびに変わる値（「誰の」「どの値を」など）は引数にする。
   - 一度決めたら変わらないもの（DB の接続など）は引数にせず、レシーバーの型のフィールドに持たせる。
   - 同じ層の似た関数とは、引数の並び順をそろえる。読む人が覚えることが減る。
1. 戻り値: 呼ぶ側は、結果として何を必要とするか。
   - 呼ぶ側がその値を使うなら返す。使わないなら返さない。
   - 失敗しうる処理なら、エラーを返す。

例として、「あるユーザーのメモを、渡された内容で保存し、保存した内容を返す」関数を考える。

| 問い                   | 答え                           | シグネチャの部品             |
| :--------------------- | :----------------------------- | :--------------------------- |
| 何をするか             | メモを保存する                 | 名前 `SaveMemo`              |
| 呼ぶたびに変わる値     | 誰のメモか、何を保存するか     | 引数 `userID string, m Memo` |
| 呼ぶ側が必要とするもの | 保存した内容、失敗したかどうか | 戻り値 `(Memo, error)`       |

これを並べると、シグネチャになる。

```go
func (s *MemoService) SaveMemo(ctx context.Context, userID string, m Memo) (Memo, error)
```

## Go のシグネチャの慣習

Go には、シグネチャの書き方に広く守られている慣習がある。

- `context.Context` は 1 つ目の引数にし、名前は通常 `ctx` にする。処理の中断（タイムアウトなど）を、呼んだ先まで伝えるために使う。呼ぶたびに変わるので、構造体のフィールドには持たせず、使う関数ごとに引数で渡す。
- `error` は最後の戻り値にする。
- 関数がエラーを返したら、呼ぶ側はほかの戻り値の中身を決まっていないものとして扱い、使わない。返す側は、ほかの戻り値をゼロ値（`Memo{}`、`0`、`""`、`nil` など）にすることが多いが、呼ぶ側はそれを当てにしない。

## 決定理由（Rationale）

- 中身から書き始めると、「何を受け取って何を返すか」が書きながら変わり、呼ぶ側との約束が後から揺れる。シグネチャを先に決めれば、呼ぶ側と呼ばれる側を別々に作ってもかみ合う。
- 一度決めたら変わらないものを引数にしないのは、呼ぶたびに同じ値を渡す手間と、渡し間違いを避けるためである。
