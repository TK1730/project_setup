# 半角・全角記号の使い分けルール

ソースコード、テストコード、コミットメッセージ、ドキュメント文章のカッコは原則すべて半角 `()` で書く。全角混入による構文エラーや検索性低下を防ぐための規則である。

## 基本ルール

| 対象               | カッコの使い分け    | 例                          |
| :----------------- | :------------------ | :-------------------------- |
| ソースコード       | 原則すべて半角 `()` | `const name = 'test (v1)';` |
| テストコード説明文 | 原則すべて半角 `()` | `'25分 (1500秒) のとき'`    |
| コミットメッセージ | 原則すべて半角 `()` | `feat(#7): ...`             |
| ドキュメント文章   | 原則すべて半角 `()` | `機能の説明`                |

英数字・記号と日本語が隣接する場合は、可読性を高めるために半角スペースを 1 つ挟む。

## Rationale (決定理由)

1. 等幅フォントでの可読性: ターミナルやエディタでは全角カッコは余白が広すぎてガタついて見えやすいため、半角で揃える。
1. 全角混入事故の防止: コードファイル内に全角文字が紛れ込むことによる構文エラーや、検索性の低下を防ぐ。
1. 業界標準への準拠: 技術文書およびプログラミングにおいて、英数・記号は原則半角とする標準に合わせる。
