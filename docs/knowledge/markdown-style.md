# Markdown の書き方

Markdown の記法の指針をまとめる。
目指すのは、ソースのまま読めて持ち運べること、長くチームをまたいで保守できること、記法が単純で覚えやすいことの 3 つである。
内容は Google の docguide の Markdown style guide をもとにしている。

## 見出し

- 見出しは `#` で書く（ATX 形式）。
  `=` や `-` の下線の形式は、どのレベルか迷うので使わない。
- `#` の後に空白を入れ、見出しの前後に空行を置く。
- H1 は文書のタイトルとして 1 つだけ置き、本文は H2 から始める。
- 見出しは、文書の中で重複しない完全な名前にする（「概要」ではなく「Foo の概要」）。
  見出しから作られるリンクのアンカーが分かりやすくなる。

## 行と空白

- 行は短く保つ。
  docguide は 1 行 80 文字までとし、リンク、表、見出し、コードブロックを例外にしている。
  どこで改行するかは [文章の書き方](/knowledge/documentation-writing.md) の「意味の区切りで改行する」に従う。
- 行末に空白を置かない。
  表示でも改行したいときは行末にバックスラッシュを置くが、できれば段落（空行）で済ませる。

## リスト

- 長く、変わりうる番号付きリストは、番号をすべて `1.` と書く（lazy numbering）。
  項目を足したり並べ替えたりしても、番号を振り直さずに済む。
- 短く変わらないリストは、ソースで読みやすいので番号を振ってよい。
- 入れ子のリストは、字下げをそろえる。
  docguide は、番号付きも箇条書きも 4 スペースで字下げすることを勧めている。

```markdown
1.  Foo.
1.  Bar.
    1.  Foofoo.
1.  Baz.
```

## コード

- 短いコード、項目名、ファイル名はインラインコード（バッククォート 1 つ）で書く。
  自動でリンクにされたくない例の URL も、インラインコードで囲む。
- 複数行のコードはフェンス（バッククォート 3 つ）で囲み、言語を必ず書く。
  インデントによるコードブロックは、言語を書けず、始まりと終わりが曖昧なので使わない。
- 端末に貼り付けるコマンドは、改行をバックスラッシュでエスケープする。

## リンク

- リンクはできるだけ短くする。
  同じ文書の集まりの中へは、完全な URL ではなく `/` から始まるパスで書く。
- 相対パスは同じディレクトリの中だけで使い、`../` は避ける。
- リンクの文字列は、内容が分かる語句にする（[文章の書き方](/knowledge/documentation-writing.md) の「内容が分かるリンクにする」）。
- 参照リンク（`[text][id]`）は、長いリンクが本文を読みにくくするときと、表のセルを短く保つときに使う。
  定義は、最初に使った節の末尾（次の見出しの前）に置く。

## 表

- 表は、素早く見比べたい表形式のデータにだけ使う。
- 空のセルが多い、行に対して列が多すぎる、セルに長い文章が入る、のどれかに当たるなら、リストと小見出しにする。

## 画像

- 画像は控えめに使い、説明するより見せるほうが簡単な場合（画面操作など）に限る。
- 目の見えない読者のために、代替テキストを付ける。

## HTML より Markdown

- 標準の Markdown で書き、HTML による工夫は避ける。
  HTML は、ソースの読みやすさと持ち運びやすさを下げる。
- Markdown でできないことがあれば、その表現が本当に必要かを考え直す。
